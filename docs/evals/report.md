## How the run works

* The runner (`evals/CostToServe.Evals`) asks each question as Dana or Luis through the studio's own agent code: the same instructions, the same eight tools with the same scope rules, and the same model deployment. Each case starts from its own in-memory decision log and package store, so cases never affect each other or the demo.
* Expected numbers are not typed by hand. The runner calls the same tools directly before the question is asked and reads the fields listed in the dataset, so the expectations follow the engine and the seed data.
* A quoted number matches when it equals the engine's value at the precision written (one unit of the last digit), so 28,186,400 matches "$28.2M".
* The Foundry step submits each turn (system prompt, question, tool calls, tool results and answer, plus tool definitions) to the isolated `proj-evals` project, which has no connections. The deterministic results are carried along as string checks so all scores appear in the Foundry portal.
